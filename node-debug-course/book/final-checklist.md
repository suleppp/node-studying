# 结业检查清单

不要凭“看完了”打勾。每项必须能口述、现场演示或给出运行证据。

## 第一阶段

- [ ] 能画出 Shell → OS → Node 进程 → 模块加载 → V8 执行的路径。
- [ ] 能解释程序文件、进程、线程、V8、Node 运行时的区别。
- [ ] 能证明两个 Node 进程不共享普通变量和模块缓存。
- [ ] 能区分 `process.cwd()`、`__dirname` 和入口路径。
- [ ] 能区分绑定不存在、未初始化、值为 `undefined`。
- [ ] 能拆出一行表达式中的调用和副作用顺序。
- [ ] 能画出调用栈并说出每个帧的返回位置。
- [ ] 能解释同步栈与 async stack trace 的区别。
- [ ] 能解释断点暂停的目标与黄色箭头的边界。

## 第二阶段

- [ ] 能从零启动/停止/重启一次 VS Code 调试会话。
- [ ] 能准确区分 Continue、Step Over、Into、Out。
- [ ] 能切换栈帧并解释 Variables/Watch 为什么变化。
- [ ] 能找到 Local、Closure、模块和全局状态。
- [ ] 能证明两个变量引用同一对象。
- [ ] 能区分 Debug Console、Node REPL 与 Terminal 的进程/上下文。
- [ ] 能使用普通、条件、异常断点和 Logpoint。
- [ ] 能说明 Watch/Debug Console 表达式的副作用风险。
- [ ] 能用三个以内断点找到同步故障首次偏离点。

## 第三阶段

- [ ] 能说出 CommonJS 的解析、加载、执行、缓存流程。
- [ ] 能修复 `exports` 与 `module.exports` 误用。
- [ ] 能解释模块单例为何不跨进程。
- [ ] 能识别循环依赖与部分初始化导出。
- [ ] 能观察 Redis 连接状态和并发连接 Promise。
- [ ] 能记录缓存 key、命令、原始值与解析值。
- [ ] 能解释 cache miss、TTL、失效和降级策略。
- [ ] 能预测 Promise executor、微任务、timer 的稳定顺序关系。
- [ ] 能解释 `await` 前后同步栈为何变化。
- [ ] 能画出 HTTP → Service → Cache/Repository → DB 路径。
- [ ] 能用证据证明第二次读取没有访问 Mongo。
- [ ] 能处理并验证错误 cause 和 HTTP 状态映射。

## 第四阶段

- [ ] 能解释 launch/attach 的生命周期差异。
- [ ] 能正确放置 `runtimeArgs`、`program` 与 `args`。
- [ ] 能用七项运行时信息核对 launch 配置。
- [ ] 能排查 source map 断点变灰。
- [ ] 能画出 npm、shell、nodemon、业务 Node 的进程树。
- [ ] 能用 PID/PPID 确认正在调试的目标。
- [ ] 能解释热重启后内存状态与外部状态的差别。
- [ ] 能说明暂停、getter、Watch 和 Inspector 的安全风险。
- [ ] 能按“现象—复现—边界—假设—证据—修复—回归”完成故障记录。
- [ ] 能完成三个引导 labs，并独立完成结业 lab 后再核对答案。
- [ ] 能把原始反馈改写为包含环境、输入、期望与实际的可判定命题。
- [ ] 能为至少三个假设写出预测证据，并主动否定其中两个。
- [ ] 能提交包含根因证据、回归矩阵和剩余风险的 PR 说明。

## 最终实战

从未打开过的 `labs/04-multitenant-cache-leak/` 开始，并按照 [第十九章](19-capstone.md) 完成八份产物：

1. 不看答案复现问题；
2. 记录进程、入口和输入；
3. 画请求数据路径；
4. 用最小观察点区分至少三个假设；
5. 找到错误值/旧值首次重新进入系统的位置；
6. 写最小修复；
7. 运行自动检查；
8. 写一页可交给同事审查的 PR/复盘说明。

全部完成后，才算从“会按调试按钮”进入“能用证据调试系统”。
