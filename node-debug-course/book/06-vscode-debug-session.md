# 第六章：第一次完整 VS Code 调试会话

## 从脑内模型到真实界面

第一阶段已经完成了一件非常重要的事：即使没有调试器，你也能预测进程、当前源位置和调用栈。现在打开 VS Code，不是为了学习一组陌生按钮，而是把已有模型和界面一一对应。

本章只使用简单同步程序。暂时不碰 Redis、Promise 或复杂框架，因为第一次会话只训练一个闭环：暂停前预测，暂停后找到对应面板，执行一步，再判断状态变化是否符合预测。

学完后，你应该能独立建立可重复调试会话，并且每次按 Continue/Over/Into/Out 前都能说明它会怎样改变当前活动帧。

### 会话开始前的检查

先说出当前选择的 launch 配置、入口文件和工作目录。然后在纸上写下第一个断点应该属于哪个进程、哪个函数帧。连这三项都没有确认，就不要按 F5。

## 6.1 先建立一个可重复会话

用 VS Code 打开课程根目录，打开 `app.js`，进入 Run and Debug 视图。选择课程自带配置 `01 - 根目录 app.js`，按 F5 启动。

一个完整会话包含：

1. 选择正确的调试配置；
2. 调试器启动正确程序；
3. 被调试进程执行并命中断点；
4. 你检查当前帧与状态；
5. 单步或继续；
6. 进程自然退出或由你停止；
7. 下次可以用相同输入重现。

如果输入、环境变量、工作目录每次都不同，就很难区分代码变化与运行条件变化。

## 6.2 五个核心动作

### Continue（继续，通常 F5）

恢复运行，直到下一个断点、异常暂停、手动暂停或进程结束。它不是“执行下一行”。

### Step Over（单步跳过，通常 F10）

执行当前源位置对应的工作，但不主动进入这一行调用的普通函数；在当前栈帧的下一个可暂停位置停下。被调用函数仍然真实执行并产生副作用。

“跳过”只是不进去看，不是“不执行”。

### Step Into（单步进入，通常 F11）

尝试进入当前行接下来会调用的函数。若一行有多个调用，可能进入你没有预期的辅助函数。此时可以 Step Out，再拆行或设置函数内部断点。

### Step Out（单步跳出，通常 Shift+F11）

让当前函数继续到返回，并在调用者恢复处暂停。若当前函数抛错，控制流可能去异常处理器，而不是正常调用位置。

### Restart / Stop

Restart 结束当前运行并按配置重新创建/连接；普通变量状态不会保留。Stop 在 launch 会话中通常结束目标程序，在 attach 会话中通常断开连接。多目标调试时先确认当前选中的会话。

## 6.3 六个主要观察区域

- **编辑器和当前行**：当前所选栈帧映射到的源位置；
- **Variables**：当前所选帧的局部、闭包、模块/全局等作用域；
- **Watch**：每次暂停重新求值的表达式；
- **Call Stack**：当前会话、线程和活动调用帧；
- **Breakpoints**：断点及异常暂停选项；
- **Debug Console**：日志输出与在当前帧上下文中的表达式求值。

注意“当前所选栈帧”。你点击 Call Stack 的另一个帧后，Variables、Watch、悬停求值和 Debug Console 都可能换到那个帧的上下文。

## 6.4 一次规范的观察顺序

暂停后固定做：

1. 看暂停原因；
2. 看当前调试会话/PID（多进程时尤其重要）；
3. 看 Call Stack 顶部和当前选中帧；
4. 读黄色箭头所在语句，区分执行前后；
5. 看该帧输入参数与局部变量；
6. 预测下一步和副作用；
7. 选择 Continue、Over、Into 或 Out；
8. 比较结果与预测。

这套顺序会阻止最常见的错误：在错误的帧里，把正确变量看成“消失了”。

## 6.5 输出在哪里

调试配置的 `console` 会影响标准输入输出所在位置：

- `internalConsole`：默认使用 Debug Console，但不适合需要交互式标准输入的程序；
- `integratedTerminal`：在 VS Code 集成终端中运行，可输入内容；
- `externalTerminal`：打开外部终端。

输出位置和表达式求值是两件事。Debug Console 既可能显示目标程序日志，也能在暂停时求值；集成终端则是一个真正运行 shell/进程的终端。

## 6.6 练习

对 `examples/05-scope/app.js` 做三次会话：

1. 全程只用 Step Over，写下你“看不到”的函数内部信息；
2. 在 `calculateInvoice` 中下断点，用 Step Into 进入其回调；
3. 使用 Restart 后确认上次修改过的运行时变量不会保留。

## 停止阅读检查

1. Step Over 是否会跳过函数的副作用？
2. Step Out 后为什么不保证回到正常调用下一行？
3. 点击 Call Stack 中的调用者后，哪些面板会切换上下文？
4. 为什么需要固定输入和工作目录？

## 本章收束：按钮只是控制流命令

现在你不应再说“F10 是跳过代码”，而应说“让当前源步骤完整执行，但不主动进入其内部函数，在当前帧下一个可暂停位置停下”。语言越准确，预测越准确。

本章默认变量名都没有歧义。真实函数里会同时出现参数、块级变量、闭包变量、模块变量和同名遮蔽。下一章把第一阶段的“绑定状态”映射到 Variables 面板，并解释为什么切换栈帧后整个观察上下文会变化。
