# 第十六章：Debug Console 实战与安全边界

## 承接多进程现实：能做到不等于可以做

前十五章不断增强观察能力：你现在可以选择正确业务进程、暂停请求、读取局部变量，甚至通过 Debug Console 调用现成的 Redis 或数据库 client。正因为能力变强，本章必须先讨论约束。

工作级调试的目标不是“尽可能多看数据”，而是在不扩大故障、不泄露敏感信息、不污染证据的前提下，取得足以区分假设的最小信息。学完后，你应能为一次观察写出环境、表达式、副作用和数据敏感度评估。

### 安全预演

假设你暂停在支付请求中，局部变量 `payment` 有一个 `refresh()` 方法和一个 `status` 字段。先分别评估读取字段、展开整个对象、调用方法、修改 status 的风险。不要因为处于“调试模式”就假设任何操作是模拟的。

## 16.1 它拥有目标进程的权力

Debug Console 中表达式在被调试进程与所选栈帧上下文执行。它可能读取进程能读取的机密、调用已连接的数据库客户端、发送网络请求、修改内存状态或终止进程。

因此把 Inspector 端口暴露给别人，风险接近把目标进程的代码执行能力交给对方。默认只绑定本机；远程调试使用认证的 SSH/容器通道，并确认环境和目标 PID。

## 16.2 观察也可能执行代码

以下操作看似只读，却不一定安全：

- 读取 getter；
- 展开 Proxy；
- 调用 `toString()`/`toJSON()`；
- 展开自定义迭代器；
- Watch 每次暂停重复求值；
- Logpoint 求值花括号表达式；
- 属性预览触发调试器/运行时行为。

对陌生对象，先读取确定为数据字段的原始值；不调用方法，不展开巨大图，不假定 getter 纯。

## 16.3 一套安全操作等级

### 绿色：通常可在本地开发环境直接做

```js
typeof userId
Array.isArray(items)
items.length
user?.id
Object.keys(plainObject)
```

`Object.keys` 也要求对象不是恶意 Proxy；绿色不是绝对无风险，而是对受控普通对象风险低。

### 黄色：先确认实现和环境

```js
service.format(user)
JSON.stringify(payload)
cache.get(key)
request.headers
```

可能昂贵、访问外部资源、泄露敏感数据或触发自定义行为。

### 红色：除非在隔离数据和明确授权下，否则不要执行

```js
redis.flushAll()
collection.deleteMany({})
user.save()
mailer.send(...)
payment.capture(...)
process.exit()
```

暂停程序并不把外部服务变成沙盒。

## 16.4 敏感数据最小化

调试身份验证问题时，也不要把完整值复制到聊天、工单或持久日志。更安全的证据：

```js
({
  hasAuthorization: typeof header === 'string',
  scheme: header?.split(' ', 1)[0],
  length: header?.length,
  tokenSuffix: token?.slice(-4)
})
```

仍要根据组织规则判断后四位是否允许。对密码、完整 token、Cookie、私钥、连接串和个人信息默认不输出。

## 16.5 暂停真实服务的影响

在共享/生产环境暂停事件循环会：

- 阻塞该进程中的其他请求回调；
- 让上游超时和重试，放大流量；
- 让租约、心跳、锁或健康检查过期；
- 改变竞争时序，使问题形态变化；
- 触发编排系统重启实例。

优先在可复现的本地/预发布环境调试。必须观察真实环境时，优先结构化日志、指标、trace、快照或采样 profiler；暂停需要明确变更与影响控制。

## 16.6 安全验证假设模板

不要输入“试试看”的任意调用，改用：

```text
假设：缓存 key 的 tenantId 错了。
只读表达式：({ expected: `tenant:${tenant.id}:user:${id}`, actual: key })
预期：两者仅 tenant 段不同。
风险：字符串求值，不访问外部系统。
结果：……
下一步：在构造 key 的纯函数处增加测试。
```

如果只有写操作才能验证，先复制到隔离测试环境，创建专用测试数据，记录清理方案和回归用例。

## 16.7 修改内存值的正确用法

例如暂停时把 `featureEnabled` 改成 `false`，能证明错误只走启用分支。但它没有解释该值为什么错误，也没有修复配置源。

修改后必须：

1. 明确标记本次会话已被污染；
2. 不再用它证明其他状态自然正确；
3. 重启进程；
4. 在配置解析或分支处写自动测试；
5. 用未经手工修改的新会话回归。

## 16.8 Inspector 网络安全

Inspector 客户端可以求值代码。规则：

- 默认使用 `127.0.0.1`；
- 不要为了方便绑定 `0.0.0.0` 并暴露端口；
- 远程使用 SSH tunnel、受控容器端口转发和访问控制；
- 不在不可信网络公开 WebSocket URL；
- 调试结束后关闭 Inspector/端口；
- 确认连接的环境，避免把生产误认成本地。

## 停止阅读检查

1. 为什么读取属性也可能产生副作用？
2. 暂停一个 Node worker 为什么可能引起上游重试风暴？
3. 手改变量证明了什么，没证明什么？
4. Inspector 端口为何等价于高权限入口？

## 本章收束：最好的证据必须同时可靠和安全

调试动作会参与系统：暂停改变时序，Watch 重复求值，getter 运行代码，远端服务继续计时。成熟开发者会把这种观察者影响写进判断，而不是把调试器视为透明窗口。

安全边界明确后，下一章把全书零件收束成一套通用流程：从模糊现象开始，确认运行对象，画边界，提出可证伪假设，找到首次偏离，完成最小修复和回归。
