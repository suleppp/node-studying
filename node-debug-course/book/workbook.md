## 2. 暂停状态快照

适用于第一、二阶段。每次暂停先填，不急着按单步：

| 项目 | 记录 |
|---|---|
| 调试会话/进程 PID | |
| 暂停原因 | 普通断点 / 条件 / 异常 / Step / debugger |
| 当前顶部栈帧 | |
| 当前选择的栈帧 | |
| 当前源位置 | |
| 这一位置执行前已发生 | |
| 执行后才会发生 | |
| 当前帧参数 | |
| 当前帧局部绑定 | |
| 闭包/模块状态 | |
| 返回后恢复位置 | |
| 下一步预测 | |
| 实际结果 | |

“当前顶部帧”和“当前选择帧”要分开。点击调用者查看不会让执行倒退。

## 3. 调用栈手绘模板

```text
顶部：函数____________  参数____________
      当前等待/执行____________
      返回结果将交给____________

      函数____________  参数____________
      当前等待____________
      返回后继续____________

底部：入口/回调____________
```

异步恢复时，再单独画一条因果箭头：

```text
谁创建 Promise/I/O → 什么事件使其完成 → 哪个 continuation 恢复
```

不要把因果箭头误画成一直存在的同步栈帧。

## 4. 跨层数据证据表

适用于第三阶段：

| 边界 | 输入 | 原始输出 | 转换后输出 | requestId/PID | 是否符合预期 |
|---|---|---|---|---|---|
| HTTP → Controller | | | | | |
| Controller → Service | | | | | |
| Service → Redis | key= | raw= | parsed= | | |
| Service → Repository | | | | | |
| Repository → Mongo | query= | document= | model= | | |
| Service → HTTP | | | | | |

第一次由“符合”变成“不符合”的边界，是下一轮深入范围。

## 5. 异步时间线

```text
时间/序号 | requestId | PID | 同步动作 | 安排的异步工作 | 完成/恢复 | 关键值
----------|-----------|-----|----------|----------------|-----------|------
          |           |     |          |                |           |
```

真实毫秒时间不一定能说明因果；requestId、Promise 创建点和完成事件更重要。断点会改变墙上时钟时间，不要用暂停时长测性能。

## 9. 阶段复盘

每阶段结束回答：

1. 我现在能预测什么，而以前只能观察什么？
2. 哪个错误模型被实验推翻了？
3. 我仍会在哪种情况下无目的地 Step Into？
4. 面对陌生代码，我的第一步是否改变了？
5. 能否不用课程示例，在自己项目找一个对应机制？
