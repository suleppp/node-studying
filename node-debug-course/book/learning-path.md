# 全书学习路线：为什么这些章节必须按顺序学习

## 1. 全书只解决一个越来越大的问题

第一章从一行最简单的命令开始：

```bash
node app.js
```

到最后，你要能处理这样的工作场景：一个由 npm 和热重载工具启动的 Node 服务，经过 Controller、Service、Redis 和 Mongo，在某个异步请求中返回旧数据；你需要确认真实业务进程，安全地收集证据，定位旧数据第一次重新进入系统的位置，写回归测试并说明修复风险。

这两个场景看似相差很远，实际只是在反复回答同一组问题：

```text
谁在运行？
  ↓
现在执行到哪里？
  ↓
为什么会来到这里、之后回哪里？
  ↓
当前能看到哪些状态？
  ↓
状态跨模块和异步边界后发生了什么？
  ↓
怎样证明第一次偏离，而不是在症状处猜？
```

## 2. 四个阶段不是四套孤立知识

### 第一阶段：建立“运行中的程序”模型

章节 1～5 依次回答：文件为什么不会自己运行、Node 进程怎样来到第一行、一行内部怎样求值、函数调用怎样保存返回路径、调试器究竟暂停谁。

这一阶段的产物不是笔记，而是一张暂停时状态图：

```text
目标 PID + 当前源位置 + 当前栈帧 + 可见绑定 + 返回位置
```

没有这张图，Variables 和 Call Stack 只是一堆界面文字。

### 第二阶段：学会有目的地观察

章节 6～9 把第一阶段模型映射到 VS Code。按钮不是新原理：Step Into 改变当前帧，Step Out 让当前帧返回，切换 Call Stack 只是选择观察上下文，Debug Console 在所选帧求值。

这一阶段的产物是一份最小观察计划：为了区分两个假设，在哪三个位置暂停，分别看什么。

### 第三阶段：让状态穿过真实 Node 项目

章节 10～13 逐步增加边界：文件变成模块，模块持有 Redis 连接，函数返回 Promise，最终请求穿过 Service、Cache、Repository 和 Mongo。

这一阶段不是分别学习四个名词，而是追踪同一个 `userId` 和用户对象如何跨越这些边界。产物是一条完整的数据证据链。

### 第四阶段：把能力放回工作环境

章节 14～19 增加工作中的复杂性：入口由配置决定，npm/热重载制造进程树，调试动作本身有安全影响，最终还必须交付复现步骤、最小修复、回归测试和复盘。

这一阶段的产物是一张可以交给同事审查的故障工单，而不只是“我把它改好了”。

## 3. 章节依赖链

```text
1 文件与进程
└─ 2 Node 启动与模块入口
   └─ 3 表达式与当前执行位置
      └─ 4 调用栈与返回路径
         └─ 5 Inspector 与暂停
            └─ 6 VS Code 会话
               ├─ 7 作用域与 Variables
               ├─ 8 Console / REPL / Terminal
               └─ 9 有目的的断点策略
                  └─ 10 CommonJS 与模块状态
                     └─ 11 Redis 连接与缓存状态
                        └─ 12 Promise 与异步边界
                           └─ 13 完整分层服务
                              └─ 14 launch.json 确认入口
                                 └─ 15 npm、子进程与热重载
                                    └─ 16 安全观察真实环境
                                       └─ 17 通用故障方法
                                          └─ 18 工作级工单演练
                                             └─ 19 独立结业项目
```

第 10、11、12 章的顺序是刻意安排的：先知道模块为什么共享连接对象，再研究连接状态和缓存内容，最后才引入让调用栈断开的异步机制。否则你看到一个 pending Promise 时，很难判断问题来自模块实例、连接状态还是 continuation 尚未恢复。

## 4. 贯穿全书的两个样本

### 样本 A：`add(10, 20)`

前半部分反复使用根目录 `app.js`。它足够小，可以只观察执行本身：声明何时初始化、调用者怎样等待、返回值何时赋给 `result`、黄色箭头怎样移动。

### 样本 B：`GET /users/u1`

后半部分把同样的问题放大到项目：哪个进程处理请求、哪个模块持有连接、`await` 前后调用栈怎样变化、缓存 key 和原始值是什么、Mongo 是否真的被调用。

两个样本不是两门课。`UserService.getById()` 中的每次函数调用，仍然遵守在 `add()` 中学到的求值和返回规则；只是它又跨越了模块、异步和外部状态。

## 5. 三种理解层级

- **能复述**：知道定义，可以解释示例。
- **能预测**：运行前能预测暂停位置、栈帧和变量变化。
- **能迁移**：面对陌生项目，能选择观察边界并建立证据链。

每章先达到“能预测”；每阶段综合练习要求“能迁移”。只达到复述，不算通过。

## 6. 学到工作水平的判据

工作水平不是知道所有 VS Code 功能，而是能稳定完成：

1. 把模糊反馈变成可复现、可判定的故障描述；
2. 证明运行的是正确代码、进程、配置和外部环境；
3. 用有限观察点找到数据第一次偏离；
4. 说明根因机制，而不只指出报错行；
5. 评估调试和修复的安全影响；
6. 提交最小修复、自动回归和清楚的交接说明。

第 18、19 章会要求你完整完成一次，不再逐步提示该按哪个按钮。
