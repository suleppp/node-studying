# Node.js 调试：从程序运行原理到真实项目

这不是一份“记住几个按钮”的速查表，而是一套可以从零自学的调试课程。目标是让你看到断点、黄色箭头、调用栈、作用域、Promise、子进程时，知道程序此刻究竟发生了什么，以及下一步应该验证什么。

## 从这里开始

1. 先读 [学习说明](book/00-study-guide.md)，完成环境检查。
2. 再读 [全书学习路线](book/learning-path.md)，理解为什么章节不能随意跳读。
3. 复制 [学习工作簿](book/workbook.md) 中的模板，保留每章的预测、观察与修正。
4. 按顺序阅读 [全书目录](book/README.md)。每章都要亲手运行对应实验，并完成章末“停止阅读检查”。
5. 遇到故障练习时，先记录证据，再看 `answers/`。不要靠猜修改代码。
6. 最后完成工作级故障工单和结业项目。它们要求你综合使用前面建立的全部模型。

## 最短启动路径

```bash
node --version
node app.js
npm run check
```

课程只要求一个仍受支持的 Node.js LTS 版本和 VS Code。基础实验不依赖 Redis、MongoDB 或第三方 npm 包。

## 目录

```text
book/       正文、术语表、检查清单
examples/   每章可以直接运行和下断点的最小实验
labs/       带故障的综合练习
answers/    故障练习的分析过程与答案
.vscode/    可直接使用的调试配置
scripts/    自动检查示例是否仍可运行
```

## 这套课程完成后的能力

你应该能够独立回答：

- `node app.js` 从磁盘文件到进程经历了什么；
- 黄色箭头所在行是“已经执行”还是“准备执行”；
- 调用栈中的每一层为什么存在、返回后去哪里；
- Variables、Watch、Debug Console、Node REPL、Terminal 各自观察的是谁；
- `require()` 为什么可能不再执行模块顶层代码；
- `async/await` 为什么会让同步调用栈断开，但程序仍能继续；
- 为什么调试 `npm run dev` 时可能附加到了错误的进程；
- 如何用“现象—假设—证据—最小实验—修复—回归”的方法定位真实项目故障。

正文不是按 API 分类的参考手册。全书只沿一条能力主线前进：先理解程序状态从哪里来，再学会观察状态，接着追踪跨模块和异步边界的状态，最后完成一次工作中的故障交付。后面的章节会明确引用前面建立的模型。
